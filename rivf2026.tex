\begin{abstract}
CICIDS2017 is published in two flow-feature releases that do not expose the same columns. The MachineLearningCVE release omits Protocol and Source Port, so aligning a nine-field schema to InSDN requires dropping those fields or reconstructing them. We evaluate one specified reconstruction---code 6 if any TCP flag is set and 0 otherwise, source port $-1$---as a controlled failure mode, not as documented practice. A row-matched counterfactual holds 207,463 CICIDS2017 flows, labels, prevalence, and seven features fixed and changes only those two encodings. Logistic-regression models trained on InSDN, including centralized and five-client FedAvg controls, then reverse in sign: ROC-AUC $0.7357$ on the original release versus $0.3545$ after reconstruction (MCC $+0.2511$ versus $-0.1915$). In the selected target slice every code-17 (UDP-coded) flow is benign, while InSDN associates code 0 with $99.7\%$ attacks, so the surrogate collides two source-domain encodings. Dropping the unavailable fields is provenance-valid here but transfers at chance for this LR ($0.5075$). Federated averaging is the evaluation setting, not the cause. Cross-dataset NIDS results should report per-field provenance.
\end{abstract}
\begin{IEEEkeywords}Intrusion detection, feature provenance, cross-dataset evaluation, federated learning, reproducibility.\end{IEEEkeywords}

\section{Introduction}
Cross-dataset tests are the usual check on whether an intrusion detector generalizes beyond its training corpus, and they routinely report severe degradation~\cite{dhooge,xenids,layeghy,cantone}, normally attributed to traffic mix, labeling, or collection environment. Federated learning (FL) is a common setting for that check, because sites share a model without pooling raw records~\cite{fedavg,flsurvey}. This paper does not propose a new FL algorithm. It asks whether a \emph{feature-provenance} choice can reverse a zero-shot verdict on identical flows.

CICIDS2017 ships a TrafficLabelling release that retains Protocol and Source Port, and a MachineLearningCVE release that omits both. Anyone aligning names to a nine-field InSDN schema must drop the absent fields or reconstruct them. We study one specified reconstruction as a controlled failure mode. The causal comparison is not InSDN versus CICIDS2017, and it is not the two public CICIDS2017 releases against each other: those releases differ in row set and prevalence. It is two encodings of the \emph{same} 207,463 CICIDS2017 flows.

The central question is: can that reconstruction reverse a source-trained linear model's ranking on identical target rows, and which field drives the reversal? Source-domain FedAvg versus centralized and local training, and an IID versus Dirichlet non-IID partition, are reported as controls. They are not hypothesized as the cause. The non-IID global model is also scored on the matched target views. A separate source-trained centralized histogram-gradient-boosting control tests whether the reversal appears outside the tested logistic-regression configurations; it is not a ceteris-paribus test of linearity.

Our contributions are: (i) a row-matched counterfactual that changes only Protocol and Source Port, with the real MachineLearningCVE release as an unmatched ecological check and a centralized control showing the reversal is not an aggregation artifact; (ii) protocol-by-label evidence that the selected reconstruction collides source-domain encodings with opposite class associations; and (iii) masking, retraining, and a target-trained within-domain control that separate ranking reliance, missing-field policy, and remaining in-domain signal, together with a label-free screen that catches placeholder substitution but not this reconstruction.

\section{Related Work and Research Gap}
\subsection{Federated intrusion detection and client heterogeneity}
FedAvg established sample-weighted aggregation of local updates~\cite{fedavg}. Non-IID clients cause objective drift, which FedProx, SCAFFOLD, and FedNova address~\cite{fedprox,scaffold,fednova}. FL-IDS work spans linear detectors~\cite{scanfl}, 5G studies with centralized and local controls~\cite{fiveg}, and deep or distillation-based defenses~\cite{flreview,fedkd}; dataset-centric evaluation finds in-domain scores near centralized ones while cross-dataset transfer degrades after label and feature alignment~\cite{datasetcentric}. We keep plain FedAvg and logistic regression as an evaluation setting.

\subsection{Cross-dataset NIDS and feature semantics}
Dataset surveys show that collection, labeling, and flow extraction constrain valid comparisons~\cite{ringsurvey}. Inter-dataset studies report large degradation even between related CIC corpora~\cite{dhooge}; XeNIDS warns against assuming interchangeable flow fields~\cite{xenids}. Later work finds asymmetric transfer~\cite{layeghy}, poor cross-dataset performance despite strong in-domain scores~\cite{cantone}, and dataset-dependent feature influence even under standardized NetFlow sets~\cite{sarhan}. Closest to our setting, Demirba\c{s} Paray and Aydos harmonize CICIDS2017 and InSDN/OVS on the ground that both came from the same extractor, so shared fields ``carry identical semantic and technical definitions''~\cite{smotefl}. Shared extractor lineage does not validate \emph{every} field of a harmonized schema when a release omits columns and a reconstruction fills them.

\subsection{Dataset defects, tooling, and release variants}
CICIDS2017 has documented defects: flow-construction and labeling faults~\cite{troubleshoot}, packet misordering and an unlabeled port scan~\cite{lanvin}, and duplicated or miscalculated features with \emph{wrong protocol detection}~\cite{rosay}. Heterogeneous-domain benchmarks materialize absent fields across \emph{distinct} datasets~\cite{hda}. Our gap is narrower: whether missingness induced by a public release of the \emph{same} corpus, plus a specified reconstruction, can invert a cross-dataset conclusion while rows, labels, prevalence, and every unaffected field are held fixed.

\section{Method}
FedAvg aggregates local parameter vectors as $\mathbf{w}_{t+1}=\sum_{k=1}^{K}(n_k/\sum_j n_j)\,\mathbf{w}^{k}_{t+1}$ with $K=5$~\cite{fedavg}. Each client runs one local pass of binary logistic regression per round. Server and clients start from a shared zero state. Centralized LR uses the same optimizer and 20 passes. Logistic regression is chosen so a sign reversal cannot be attributed to a deep architecture; it is not claimed to be an operational NIDS. A later centralized nine-field HistGradientBoosting control, not a federated model and not matched to LR in capacity or representation, tests whether the reversal appears outside these LR configurations.

\subsection{Feature-shift diagnostic}
For source feature $j$ we record the two-sample Kolmogorov--Smirnov distance $D_j=\sup_x|F_{sj}(x)-F_{tj}(x)|$ on the standardized column. KS compares empirical CDFs on the numeric order of values. Protocol codes $\{0,6,17\}$ are nominal labels, so that order is arbitrary; we therefore treat total variation (TV) between category proportions as the primary marginal comparison for protocol, and report KS only as a supplementary numeric-order statistic. Neither is a significance test: the study uses the distance, not a $p$-value.

We keep the trained IID global model fixed, replace one standardized feature by zero (the source-training mean), and compute $\Delta A_j=A^{\mathrm{mask}(j)}_t-A^{\mathrm{full}}_t$ on target ROC-AUC. Positive $\Delta A_j$ means masking \emph{raises} ranking quality, so the learned contribution of that column harms target ranking; negative $\Delta A_j$ means the column carries transferable ranking signal. Masking is not retraining, not imputation, and not a causal effect of ``removing'' a raw field: correlated features share credit, and a constant column cannot reorder scores even if it moves a fixed-threshold metric.

\subsection{Label-free provenance screen}
From the source-training column $x_j$ and the unlabelled target column $\tilde{x}_j$ the check flags a column when
\begin{equation}
\frac{\mathrm{sd}(\tilde{x}_j)}{\mathrm{sd}(x_j)}<\tau_v
\quad\text{or}\quad
\Pr\!\left[\tilde{x}_j\notin[\min x_j,\max x_j]\right]>\tau_r,
\end{equation}
with $\tau_v=\tau_r=0.01$. A placeholder such as a constant sentinel typically triggers both. For integer-coded fields we also record TV between category proportions and a mass-collapse rule (a source category with mass $>5\%$ falling below $1\%$ on the target). These rules are compared with $\Delta A_j$, not treated as causal ground truth.

\section{Experimental Protocol}
\subsection{Source data, mappings, and the three target views}
Prepared InSDN~\cite{insdn} contains 343,889 records (68,424 normal; 275,465 anomaly). The stored protocol field takes integer codes $\{0,6,17\}$. We do \emph{not} treat those integers as established IANA protocol identities: the files do not include packet-level confirmation, and code 0 in this InSDN extract is uniformly portless (source and destination port 0) with attack prevalence $99.7\%$. Codes 6 and 17 coincide with the usual TCP/UDP numbers in these CSVs, but that coincidence is not a proof of extractor semantics.

Each seed draws a stratified 30,000-record InSDN sample (24,000/6,000 train/test) and 30,000 records from each target view. Because \textsc{tl} and \textsc{cf} share row order and labels, one seeded draw selects the same rows from both.

All three target views describe the same CICIDS2017 capture files~\cite{cicids}: Monday benign, Friday DDoS, Friday PortScan. \textsc{tl} is built from TrafficLabelling and keeps the original Protocol and Source Port fields. \textsc{mlcve} is built from MachineLearningCVE, which omits both; preserving a nine-field schema then requires a policy for the absent columns. We evaluate one lossy rule, chosen because TCP flags remain when Protocol does not, so a practitioner keeping the InSDN schema might infer ``TCP versus other'': protocol becomes 6 when any TCP flag is positive and 0 otherwise, and every source port becomes $-1$. It is a specified intervention, not a cited standard.

Comparing \textsc{tl} with \textsc{mlcve} alone is confounded: the two releases survive cleaning and de-duplication differently (Table~\ref{tab:mirrors}). The \textsc{cf} view removes that confound. It is derived from the finished \textsc{tl} test split, overwriting only \texttt{ip\_proto} and \texttt{tp\_src}. Re-running the cleaner with those columns suppressed would change the row set, because missing-value filtering and de-duplication key on them. Scripts abort if the seven unaffected columns and labels are not identical or if more or fewer than two columns differ. The counterfactual identifies the effect of this two-field intervention on these rows and the models scored here. It does not identify a property of federated averaging, of all missingness policies, or of NIDS transfer in general.

The nine model inputs---protocol, source and destination port, packet and byte counts, duration in seconds, packet and byte rates, and average packet size---are referenced by name, not position. InSDN supplies them from Protocol, Src/Dst Port, Tot Fwd/Bwd Pkts, TotLen Fwd/Bwd Pkts, Flow Duration$/10^{6}$, Flow Pkts/s, Flow Byts/s, and Pkt Size Avg. CICIDS2017 supplies the corresponding TrafficLabelling names, or the flag surrogate and sentinel port when MachineLearningCVE omits those columns. Duration is treated as microseconds following CICFlowMeter documentation; rate and size fields are passed through. This is syntactic alignment of CICFlowMeter-family columns, not a proof that every formula is identical across extractor versions. A duplicated flow-duration column, identical to duration in seconds in every row~\cite{rosay}, is stored but unused as a model input.

During preparation, infinities (and CICIDS string tokens Infinity/inf) become NaN, non-numeric entries are coerced to NaN, and rows with NaN in any used column or the label are dropped; missing forward or backward packet or byte counts are filled with 0 before that drop. Negative durations and rates are finite and are retained. At evaluation, any remaining non-finite values among the nine inputs are replaced by 0, then z-scored. A source-only standard scaler is fit on InSDN training features and applied unchanged to the InSDN test partition and all three target views. No target-domain fit, fine-tuning, or threshold selection is performed in the zero-shot evaluation. Labels: InSDN normal$\rightarrow0$, anomaly$\rightarrow1$ (sampled 5,969 benign / 24,031 attack); target normal$\rightarrow0$, ddos/portscan$\rightarrow1$.

\subsection{Partitions and measures}
IID FL splits shuffled training records equally among five clients; non-IID FL allocates each class by a Dirichlet distribution with $\alpha=0.5$. Both run 20 rounds fixed \emph{a priori}. Predicted labels use threshold $0.5$; ROC-AUC and PR-AUC (trapezoidal area under the precision--recall curve) use scores. The random PR baseline is the attack prevalence, 0.801 in InSDN. At seed 11 the Dirichlet split yields client sizes 1,669 to 11,950 and benign shares $0.5\%$ to $38\%$. Centralized LR uses the same 24,000 training records; local-only LR is an unweighted mean of five client models, not an ensemble. The classifier is scikit-learn SGD with log loss, $\eta=0.01$, L2 $\alpha=10^{-4}$, seeds 11, 23, 42, 77, 101, Python 3.11 / NumPy 2.2.6 / pandas 2.3.1 / scikit-learn 1.7.2. A robustness control trains a source-only nine-field HistGradientBoostingClassifier with protocol as a native categorical feature (stored code 0 is a category, not a missing token), learning rate $0.1$, 100 iterations, at most 15 leaves, at least 20 samples per leaf, L2 $1.0$, no early stopping and no class weight. Hyperparameters are fixed a priori; that model is centralized, not federated, and is not capacity-matched to LR. A separate seven-field HGB is source-retrained after dropping the two MLCVE-absent columns.

\subsection{Reconstruction reverses the verdict on identical rows}\label{sec:cf}
The seven-field intersection of Section~\ref{sec:ablation} is provenance-valid, not predictively adequate. The nine-field comparison isolates the cost of this reconstruction. The same five IID FedAvg models are scored on all three views (Table~\ref{tab:cross}). On \textsc{tl}, transfer is degraded ($0.9324\rightarrow0.7357$ ROC-AUC) but remains informative (MCC $+0.2511$, PR-AUC $0.4520$ against prevalence $0.2765$). Overwriting only the two encodings sends ROC-AUC, PR-AUC, balanced accuracy, and MCC below their no-skill baselines, and F1 to $0.3558$.

The real \textsc{mlcve} release lands close to the counterfactual ($0.3441$ against $0.3545$) but differs in row set and prevalence, so it corroborates rather than identifying the matched effect. The centralized model shows the same reversal ($0.7490\rightarrow0.3544\rightarrow0.3447$). Dirichlet non-IID FedAvg ($\alpha=0.5$) also reverses on the matched views (ROC-AUC $0.7297$/$0.3507$; five-seed paired $\Delta$AUC $0.3791$). A fixed-model factorial on the IID FedAvg models isolates the driver: replacing protocol alone reduces ROC-AUC from $0.7357$ to $0.3365$, whereas replacing source port alone raises it to $0.7522$; the combined reconstruction remains $0.3545$. A source-trained centralized nine-field categorical HistGradientBoostingClassifier, not a federated model and not matched to LR in capacity or representation, stays above chance on the paired views ($0.9602$/$0.9080$; unmatched MLCVE $0.9073$). On that same nine-field model, protocol-only reconstruction leaves ROC-AUC at $0.9601$, while source-port substitution yields $0.9096$; that remaining loss is not claimed for every tree. A different source-retrained seven-field HGB reaches $0.9603$ on the paired views, which coincide once those two fields are omitted from training, and $0.9592$ on unmatched MLCVE. Sign reversal was observed in the tested logistic-regression configurations, including one-hot protocol, but not in these HGB controls.

\subsection{Protocol codes and label associations}
Table~\ref{tab:proto} reports stored integer codes against binary labels on the prepared files. In the \textsc{tl} test split, all 62,901 code-17 (UDP-coded) rows are benign, and every DDoS row has \mbox{code 6}. PortScan is not exclusive to \mbox{code 6}: three PortScan rows have code 0, which is the $3.7\%$ attack rate on \textsc{tl} code 0 in Table~\ref{tab:proto}; those three rows remain after reconstruction, so \textsc{cf} code 0 is not exactly attack-free. InSDN associates code 0 with $99.7\%$ attacks and code 17 with $0.3\%$ attacks. Every protocol disagreement between \textsc{tl} and \textsc{cf} is $17\rightarrow0$ (30.32\% of rows). The surrogate therefore writes the source's strongly attack-associated code onto the target slice's entirely benign code-17 population. That is a semantic collision in the source-model feature space, not a change of the underlying flows. We do not claim the fitted coefficients implement a perfect decision rule from protocol alone; masking and retraining below test reliance.

\subsection{Localizing the reversal}\label{sec:ablation}
Masking the fixed model localizes the ranking reversal to protocol, the only field whose $\Delta A$ changes sign: on \textsc{tl}, masking protocol costs $0.1438$ ROC-AUC ($\Delta A=-0.1438$), whereas on \textsc{cf} masking the surrogate \emph{gains} $0.2647$. The real release agrees ($+0.2103$). Protocol TV is $0.3532$ on \textsc{tl} and $0.1489$ on \textsc{cf}---the harmful encoding looks \emph{closer} to InSDN on identical rows. Numeric-order KS repeats the direction ($0.3532$ versus $0.0992$) but is not the appropriate categorical comparison.

Source port is a different failure. Masking it \emph{gains} $0.0165$ ROC-AUC on \textsc{tl} ($\Delta A=+0.0165$), so its learned contribution harms TL ranking slightly; we include the field because it is part of the InSDN schema and is the other MLCVE-absent column, not because it is a justified NIDS predictor. On \textsc{cf} every value is the sentinel $-1$, KS is maximal, and masking leaves ROC-AUC unchanged to four decimals: a constant adds the same amount to every logit and cannot reorder scores. It does move the operating point, shifting \textsc{cf} MCC by $+0.0186$. Protocol therefore localizes the ranking reversal; source port does not.

Retraining is a different intervention (Table~\ref{tab:ablation}). Dropping protocol before training costs source F1 ($0.9580\rightarrow0.9118$) and collapses the \textsc{tl}--\textsc{cf} gap ($0.4953$, $0.5157$, $0.4668$). On matched \textsc{cf} rows, dropping the unavailable field reaches $0.5157$ while reconstructing it reaches $0.3545$. One-hot encoding protocol is the best \textsc{tl} configuration ($0.7472$) yet barely moves \textsc{cf} ($0.3630$). Removing both ports lowers \textsc{tl} ROC-AUC to $0.7062$; masking attributes most of that ranking loss to destination port ($\Delta A=-0.0605$), which every view supplies. The seven-field intersection drops both MLCVE-absent fields rather than reconstructing them: source F1 $0.9082$, chance-level transfer $0.5075$, and \textsc{tl}$=$\textsc{cf} to every reported digit. In this LR experiment, dropping unverified unavailable fields and retraining is a conservative provenance-valid baseline. It is not a useful detector for this linear model, and it is not shown to dominate every alternative imputation or every classifier family.

\subsection{Target-trained within-domain control}\label{sec:oracle}
Zero-shot scores cannot separate lost information from changed meaning. Table~\ref{tab:ablation}(b) trains and evaluates logistic regression inside one view (its own scaler, 80/20 of that view's 30,000-row sample). This is a within-domain diagnostic for this model class, not an information-theoretic upper bound.

On the matched \textsc{tl}/\textsc{cf} samples the control reaches $0.8820\pm0.0630$ against $0.8995\pm0.0553$, while zero-shot transfer is $0.3545$ against $0.7357$. Pairing by seed, the in-domain gap is $0.0175$ (95\% CI $[0.0069,0.0280]$, \textsc{tl} ahead on all five seeds) and the zero-shot gap is $0.3813\pm0.0052$ on the 30,000-row samples. Reconstruction therefore costs a small, consistent amount of in-domain LR signal and changes much more of what the source encoding means. The real \textsc{mlcve} release agrees ($0.8956$ in-domain, $0.3441$ transfer). The seven-field control reaches $0.7200$ in-domain on \textsc{tl} and \textsc{cf} and $0.7117$ on \textsc{mlcve}, which the source model does not capture at $0.5075$.

\subsection{What a label-free preflight check can and cannot catch}\label{sec:screen}
Among 27 column--view pairs the screen flags two on all five seeds and no others: source port of \textsc{cf} and of \textsc{mlcve} (ratio $0.0000$, out-of-range $1.0000$). No unflagged column falls below ratio $0.352$ or exceeds out-of-range $0.0028$; the byte-rate column is 31 to 48 times more dispersed yet has $\Delta$AUC $0.0000$.

The reconstructed protocol keeps a plausible dispersion ratio ($0.5672$ on \textsc{cf}) and never leaves the source range. TV scores the harmful encoding as closer ($0.1489$ against $0.3532$). The mass-collapse rule fires on all three views, including uncorrupted \textsc{tl}, where protocol 0 falls from $35\%$ of source mass to $0.04\%$. Silence is not evidence of sound provenance; metadata recorded at preparation time is.

\section{Discussion}
The matched contrast cannot be attributed to attack mix, labeling, collection environment, sampling, or FedAvg averaging: rows, labels, prevalence, seven features, scaler, and threshold are shared, and the centralized model reverses too. The reversal is consistent with a protocol-dependent shortcut in this linear model on this slice: the reconstruction maps the target's benign code-17 population onto InSDN's attack-associated code 0. Rosay et al.\ report wrong protocol detection in these releases~\cite{rosay}; we quantify what one reconstruction of that field does to a verdict.

A provenance-valid intersection is not a useful detector for this LR: $0.5075$ is an honest non-answer. A source-retrained seven-field HGB, not the nine-field HGB above, remains strong on those fields. Other missingness policies were computed under \texttt{results/phase\_b/missingness/}; they are not a classifier benchmark and are not claimed to fail universally. Non-IID source results in Table~\ref{tab:results} show that heterogeneity can move operating-point metrics without moving ROC-AUC; scoring that non-IID model on the matched views still reverses, so reconstruction is not an FL mechanism.

\section{Threats to Validity and Reproducibility}
The headline comparison uses tabular flows, not packets, one source corpus, one restricted CICIDS2017 slice, logistic regression, five repeated stratified holdouts from a finite corpus, and one reconstruction rule. The five seeds are not independent NIDS datasets. A source-trained centralized nine-field categorical HistGradientBoostingClassifier did not reverse on these views; that control is not federated, is not capacity- or representation-matched to LR, does not establish tree-ensemble robustness in general, and does not show that categorical encoding repairs LR. Neural models, other reconstructions, and other dataset pairs remain untested. Source-domain HGB ranking on InSDN is near ceiling (ROC-AUC $0.9999$). About $34.86\%$ of source-test rows match a training feature vector; the overlaps are label-consistent and are not target-label leakage, so that in-domain score is not evidence of broad external validity. Protocol code 0 is characterized empirically, not identified at the packet layer. Masking reports model reliance, not a unique causal feature effect. Binary labels and the 0.5 threshold limit external validity.

\section{Artifact Availability}
Preparation records per-file read-or-reconstructed status and publishes SHA-256 checksums. A verifier checks quoted numbers against tracked files in \texttt{results/verified/} and \texttt{results/phase\_b/} without third-party CSVs. Regenerating models needs those CSVs: B.2 and some missingness policies replay tracked checkpoints, whereas B.1, B.3, and B.4 retrain source-only models. The camera-ready artifact is Git tag \texttt{rivf2026-camera-ready}: \url{https://github.com/thtcsec/rivf2026-federated-edge/tree/rivf2026-camera-ready}. Third-party datasets are not redistributed.

\section{Conclusion}
On one fixed set of 207,463 CICIDS2017 flows, a specified reconstruction of two MachineLearningCVE-absent fields moves InSDN-trained logistic regression from ROC-AUC $0.7357$ to $0.3545$. A centralized LR model and Dirichlet non-IID FedAvg reproduce the reversal, so neither federated averaging nor an IID partition is the cause. Protocol replacement alone produces the ranking reversal in that LR; source-port substitution does not. The selected slice labels every code-17 (UDP-coded) flow benign, while InSDN associates code 0 with $99.7\%$ attacks; the surrogate collides those encodings. A source-trained centralized nine-field categorical HistGradientBoostingClassifier does not reverse ($0.9602$/$0.9080$). That control is not matched to LR in capacity or representation, so the sign reversal is reported for the tested logistic-regression configurations rather than for all intrusion detectors. Dropping the unavailable fields avoids the below-random LR result but transfers at chance for that LR ($0.5075$). Cross-dataset NIDS evaluations should report feature provenance per field.
